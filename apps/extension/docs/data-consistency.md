# 书签写入、导出和 WebDAV 一致性

## 本地写入

`bookmarkStorage` 的所有写方法通过 `BookmarkCommands` RPC 进入 background 的同一串行队列。background 自身也使用同一队列；原始实现内部的嵌套调用不重复排队。清空书签与分类也走该入口，禁止在 UI 中直接删除对应 storage key。

`getExportSnapshot` 与写入共用队列，读取书签正文及分类；`exportService` 组合其他导出数据。导入通过 `toImportedBookmark` 保留正文并重新映射分类。本次保留既有存储格式，不提供跨所有存储项的崩溃事务或整个资料库的原子快照。

同步下载前保存本地书签元数据，应用下载时在写入队列内重新比较：期间被编辑或彻底删除的记录及其下载正文不再写入，留待后续同步重新合并。

## WebDAV

同步及清空远端数据均先获取同步目录的独占、递归 WebDAV `LOCK`。所有 PUT、MKCOL、DELETE 请求携带锁令牌条件；令牌失效时服务端拒绝旧写入。`sys.json` 的旧标记只用于兼容旧客户端，不再承担互斥保证。

协议依据：[RFC 4918 的锁与 If 条件](https://www.rfc-editor.org/rfc/rfc4918.html#section-7)。服务端必须正确实现独占深度锁和条件请求。请求租期为 600 秒，服务端可能缩短租期；到期后本轮中止，下一轮重新读取合并，不无条件覆盖。批量上传会等待全部已启动操作结束后才释放锁。

不支持 LOCK 的服务器明确返回 `lockingUnsupported`，不降级到不安全的模拟锁；锁冲突或过期返回 `conflict`。需要使用支持 WebDAV 锁的服务。扩展退出后未释放的锁依赖服务端租期回收。

## 验证

- 单测：跨多个模块上下文的并发创建、更新、去重、嵌套批量操作、失败后继续写入、旧同步结果防覆盖、JSON 正文往返。
- WebDAV 测试：竞争锁、过期旧写入、条件头、失败释放、不支持锁时停止。
- Chromium E2E：两个管理页面同时导入，以及真实 JSON 导入和下载导出的正文验证。
- 人工验证：在 Chrome、Firefox、Edge 的管理页与 popup 同时保存不同书签；在两台真实设备连接同一 WebDAV 目录时同步，并检查锁冲突后的重试。自动测试不能替代具体服务商兼容性验证。
