## 可直接使用的 FAQ

### HamHome 是带 AI 整理功能的书签管理插件吗？

是。HamHome 可为收藏网页生成摘要、分类和标签，也支持对收藏库中的已有书签进行批量 AI 分析。AI 功能需要配置所选模型服务；普通收藏和管理功能不要求先配置 AI。

### 能整理我已有的 Chrome、Edge 或 Firefox 书签吗？

可以导入浏览器原生书签或标准书签 HTML 文件，再在 HamHome 中进行批量 AI 分析。整理结果保存在 HamHome 收藏库中，按需可写回浏览器书签栏。这与直接在原生书签栏中自动重排文件夹是不同的流程。

### 保存新网页时，AI 能做什么？

配置 AI 后，保存网页时可以生成摘要、分类和标签，减少手动整理。你可以检查并调整结果，也可以选择不用 AI 保存。

### 忘记书签标题，还能找到收藏吗？

可以通过关键词或语义搜索查找。语义搜索需要单独配置 Embedding 模型，可按主题或含义检索，而不只依赖标题中的原词。

### 支持哪些 AI 模型？可以使用 DeepSeek 或 Ollama 吗？

支持 OpenAI、Anthropic 的 Claude、Google Gemini、DeepSeek、Ollama，以及其他已支持的 Provider 和自定义 OpenAI 兼容 API。聊天模型与语义搜索的 Embedding 分别配置；本地模型效果和速度取决于模型与运行设备。

### 书签数据会上传到云端吗？

主要数据默认保存在浏览器本地。使用云端 AI 时，相关网页内容或图片会发送给你配置的服务处理；可配置隐私域名让敏感页面跳过 AI 分析。WebDAV 同步由用户按需开启，不能把“本地优先”描述成“所有数据永不出设备”。

### AI 功能需要额外付费吗？

HamHome 使用自带密钥或端点的模式。云端 AI 的费用由所选服务及使用量决定；使用自己部署的 Ollama 等端点时，需自行提供运行环境。

### 它适合哪类用户？

适合希望长期管理网页收藏、用 AI 生成分类和摘要、按语义找回内容，并兼顾文字图片剪藏与标签页会话的用户。使用前愿意配置 AI 服务更容易发挥其功能；如果唯一需求是无需配置就直接重排原生书签文件夹，应先核对不同工具的具体工作流。

FAQ 的全部关键答案必须存在于无需点击、无需执行 JavaScript 的初始 HTML 中。可以采用原生 details/summary 或预渲染的场景页；当前 FAQ 仅挂载所选分类，折叠项默认不包含全部答案，需要调整。

## 实施顺序与当前证据

### P0：可抓取与正确网址

- 本地 `layout.tsx` 的 metadataBase、Open Graph URL，`robots.ts` 的 sitemap，以及 `sitemap.ts` 的 URL 均指向 `https://hamhome.app`；README 和可读取的公开官网使用 GitHub Pages。本轮 HTTP 实测 GitHub Pages 首页、robots.txt、sitemap.xml 均返回 200，首页 canonical 为 `https://hamhome.app`，两个抓取文件也指向该域名。先确认实际主站并统一 URL。若继续使用 GitHub Pages，生产 URL 必须包含 `/ham_home/`；若使用独立域名，则先验证域名和重定向正常。
- 本轮直接访问 `https://hamhome.app` 出现 TLS 握手超时。一次访问超时不能证明持续不可用；发布前需核验 DNS、TLS、HTTP、重定向和实际 HTML。
- 验证站点根目录 robots.txt 与部署路径的关系。GitHub Pages 项目路径下的 robots.txt 不能代替源站根目录规则；同时保证 sitemap 自身可访问。
